# reload-docs — 설계 문서 재적재 (조각)

> **왜**: 조각은 단일 기준 문서(`CLAUDE.md`) + 시스템별 `docs/*_SYSTEM.md`에 설계 결정·제외 결정·
> **뒤집은 결정과 그 이유**가 전부 박혀 있다(`DOC_DISCIPLINE.md`). **컴팩트가 일어나면 읽어둔
> docs/ 본문이 컨텍스트에서 사라져** 설계 근거 없이 결정하게 된다. 이 스킬이 그 공백을 채운다.
>
> 참고: `CLAUDE.md`와 메모리(`MEMORY.md`)는 매 세션 자동 주입돼 컴팩트 후에도 남는다 →
> **실제 공백은 `docs/`와 `C:\project\common`**. 그래서 README 색인 + 시스템 문서가 핵심이다.
>
> ⚠ 조각의 결정 로그는 **취소선으로 뒤집힌 결정**이 많다(`~~A~~ → B`). 요약이 아니라 **원문을 읽어야**
> 지금 유효한 쪽을 안다. 컴팩트 요약은 뒤집기 전 결정을 보존하지 않는다.

## 실행 순서

### 1. 척추 먼저 (필수)

- **`docs/README.md`** — 색인. 문서 목록 + **구현 현황표**(§2) + **검증 루틴**(§3) + 아키텍처 원칙(§4).
  이거 하나로 "무엇이 있고 무엇을 만지면 무엇이 도는지"가 잡힌다. §2의 ✅/🔴/⏸ 표시가
  **현황 정본**이다 — CLAUDE.md §14 요약과 어긋나면 README가 이긴다.
- **`CLAUDE.md`** — 기둥 4개(쓰기 마찰 최소화 · 감성적 미니멀 · 내 기록은 내 기기에 ·
  광고가 글쓰기를 막지 않는다) · 서버 경계 · 구독 정책 · **§12 결정 로그**.
  자동 주입돼 있어도 **결정 직전이면 §12를 한 번 더 짚는다**.

### 2. ★ 공용 문서 재적재 (`C:\project\common`) — 항상

이 프로젝트 문서만이 아니라 **여러 프로젝트가 공유하는 기준 문서**를 함께 읽는다.
`C:\project\common` 아래 **`.md` 전부**:

- `BUSINESS_INFO.md` — 사업자·서비스 정보 **단일 출처**(법적 상호·사업자번호·통신판매업 신고번호·
  주소·스토어 계정·연락처·결제/광고 ID). 처리방침·약관·스토어 등록·전자상거래법 §13① 표시의 기준값.
- `PLAY_RELEASE_AUTOMATION.md` — Play 출시·업로드 자동화 절차와 함정.
- 새 문서가 생기면 함께 읽는다(`ls C:/project/common/*.md`로 목록 확인 후 전부).
- `.claude/`(스킬·에이전트 정의)는 도구라 제외 — 호출 시 로드된다.

> **왜**: 한 프로젝트 세션이 **크로스-프로젝트 사실**(Play 계정 상태·법적 정보·릴리스 절차)을
> 낡은 기억으로 오보하기 쉽다. 조각에서 실제로 겪었다 — **Play 콘솔 계정이 바뀌었는데
> 옛 계정 실측치로 판단**(CLAUDE.md §14), **Play 계정 유형이 조직→개인으로 되돌아간 것**(2026-08-17).
> 공용 문서가 정본이니 재적재 때 같이 읽는다.

### 3. 규율 문서 (작업이 문서·법무·다국어에 닿으면)

- **`docs/DOC_DISCIPLINE.md`** — 결정 先문서 · 취소선 정정 · 색인 유지 · **날짜 절대화** ·
  **§6 추정 금지**(도메인·라이브러리 사실은 출처로).
- **`docs/ARCHITECTURE.md`** — 서버 경계(common_server vs 조각 서버) · 신원 흐름 · 연동 계약.
- **`docs/I18N_SYSTEM.md`** — 문자열 규약 · **§4.5 `check:i18n`이 못 잡는 종류**(수 일치 등).
  화면 문자열을 하나라도 건드리면 읽는다.

### 4. 건드리는 시스템의 `*_SYSTEM.md`

README §1 색인에서 작업 영역의 문서를 골라 읽는다:

| 만지는 곳 | 읽을 문서 |
|---|---|
| `features/diary/` · `db/` | `DIARY_SYSTEM.md` · `DATABASE.md` |
| `features/backup/` · `server/app/api/v1/backup/` | `BACKUP_SYSTEM.md` |
| `features/ai/` · `server/shared/ai/` · 리포트 화면 | `AI_REPORT_SYSTEM.md` |
| `features/subscription/` · `features/entitlement/` · 결제·Play·RC | `MONETIZATION_SYSTEM.md` |
| `features/support/` · 공지·문의·로그인 | `SUPPORT_SYSTEM.md` |
| `features/legal/` · 처리방침·약관 | `MONETIZATION_SYSTEM.md` §5 + `AI_REPORT_SYSTEM.md` §9 |
| `locales/` · 화면 문자열 | `I18N_SYSTEM.md` |
| 운영 콘솔 | `ADMIN_SYSTEM.md` |

> **"전부 다 읽어"** 지시면 → 1·2·3 + `docs/*.md` 전체.
> 특정 작업을 이어가는 중이면 → 1·2 + 그 영역 문서만으로 충분(컨텍스트 절약).

## 🔴 컴팩트 후 가장 자주 어기는 불변식 — 재적재 때 반드시 확인

원문을 읽기 전에 이것부터 기억에서 되살리지 말고 **문서에서 확인**한다.

| 불변식 | 어디 |
|---|---|
| **AI = "저장하지 않습니다"(O) / "볼 수 없습니다"(X)** · **백업 = "우리는 읽지 못합니다"(O) / "아무것도 저장하지 않습니다"(X)** — **정반대다.** 한 화면에 섞지 않고 i18n 키도 `ai.notice.*` / `backup.notice.*`로 분리 | CLAUDE.md §5.1 |
| **LLM 키를 앱에 넣지 않는다.** 반드시 조각 서버가 프록시한다 | CLAUDE.md §5.1 |
| **프록시는 본문을 로그에 남기지 않는다** — `reportError()`에 요청 본문을 넘기지 않는다 | CLAUDE.md §5.1-5 |
| **PIN·패턴 평문 저장 금지** · 암호화 키는 기기 SecureStore + 복구 코드, **서버는 키를 갖지 않는다** | CLAUDE.md §7.1 · §12 |
| **`C:\project\common_server` · `volleyball` · `my_word`는 읽기 전용.** 수정하지 않는다 | 사용자 지시 |

| 화면 문자열은 **전부 `t()`**, DB·SecureStore에는 **코드/id만** | CLAUDE.md §9.1 |

## 모든 작업은 문서부터 — 그다음 개발 (착수 전 항상)

> **왜 여기 적나**: `CLAUDE.md §11`이 표준 작업 순서를 **① 플랜 → ② 문서 → ③ 개발 → ④ 검증**으로
> 못박았고, 메모리에도 `docs-before-code`가 있다. 컴팩트로 직전 맥락이 날아가면
> "코드부터 고치고 문서는 나중에"로 흐르기 쉽다.

코드를 건드리기 **전에**:

0. **기존·상충 결정부터 읽는다 (선행 — 가장 자주 빼먹는 단계)** — 내 계획을 적기 **전에**,
   그 영역의 `docs/*_SYSTEM.md`와 `CLAUDE.md §12`에서 **그 주제에 이미 내려진 결정**을 `grep`으로 찾는다.
   *"이미 정해진 게 있나? 내 변경이 그걸 뒤집나?"*
   ⚠ **"UI 한 줄 수정"도 문서화된 동작**(고지 문구·게이트 조건·캡·기간 규칙)을 바꾸면 시스템 변경이다.
   ⚠ 조각은 **뒤집힌 결정이 취소선으로 남아 있다** — 검색 결과의 첫 줄이 `~~취소선~~`이면 그건 옛 결정이다.
1. **설계 결정을 해당 문서에 먼저 적는다** — 새 결정은 `docs/*_SYSTEM.md` 또는 `CLAUDE.md`에
   **먼저** 반영하고 색인(`docs/README.md` §1·§2)을 갱신한다. 기존 결정을 뒤집으면
   **취소선 정정으로 보존**한다(`DOC_DISCIPLINE.md` §1).
2. **그다음 개발에 착수한다.**
3. **끝나면 문서를 진실과 일치시킨다** — README §2 현황표를 갱신하고, 새 검증 명령은 §3에 등록한다.

## 버그를 발견하면 — 문서 작업을 빼먹지 마라

> **왜 여기 적나**: 검증 도중 버그를 찾으면 고치고 끝내버리고, **"왜 못 찾았나"와 "형제 버그"**를
> 빠뜨리기 쉽다. 컴팩트 직후 특히 그렇다. 메모리 `sibling-bug-sweep`·`keep-docs-current`가
> 정확히 이걸 요구한다. 발견 = 고침 + **3종 기록**이 끝나야 완료다.

1. **현재 오류 등록** — 무엇이 틀렸나를 해당 `*_SYSTEM.md`에 적고, **재현·가드**(check 스크립트)를 건다.
   ⚠ 가드는 **고치기 전에 실패해야** 한다. 통과만 확인하면 허위 오라클이다.
2. **왜 이전 검증이 못 찾았나** — 어떤 가정이 이걸 가렸나를 한 절 적는다.
   본보기: `MONETIZATION_SYSTEM.md §6.1.7` *"탐지 실패가 아니라 경로 미주행이다"*.
   ⚠ 조각에서 반복된 사각 두 가지: **① 파생 상태만 보고 원문(웹훅 `raw`)을 안 봤다**
   **② 이름·주석이 코드와 반대인데 그걸 믿었다.**
3. **형제 버그 훑기** — 같은 클래스의 다른 사례를 능동적으로 전수 조사한다.
   본보기: `I18N_SYSTEM.md §4.5` — 하나인 줄 알았던 `1 entries`가 **50개**였다.

## 끝나면

- 무엇을 다시 읽었는지 **한 줄로** 보고하고 중단됐던 작업을 이어간다. 요약 재설명은 하지 않는다.
- 읽은 내용 중 **현재 작업과 충돌하는 설계·제외 결정**이 있으면 먼저 짚는다 — 추정으로 덮어쓰지 않는다.
- 이번 세션에 버그를 발견했다면 위 **3종 기록**이 다 남았는지 자가 점검한다.

## 커밋 전 검증 (`CLAUDE.md §11 ④`)

```bash
npm run typecheck && npm run lint && npm run check:i18n
npm run check:shared        # features/ai/{types,prompt,period}.ts를 고쳤으면 필수
```

나머지 영역별 검사(`check:backup-crypto` · `check:subscription` · `check:ai` · `check:legal` ·
`check:admin` · `check:release-env`)는 **`docs/README.md` §3이 정본이다.** 여기에 복제하지 않는다 —
두 곳에 적으면 어긋난다.

## 자동 트리거 (훅)

`.claude/settings.local.json`의 `SessionStart`(matcher `compact`) 훅이 컴팩트 완료 후
"reload-docs를 실행하라"는 안내를 컨텍스트에 주입한다. 훅을 끄려면 그 항목을 지우면 되고,
이 스킬은 `/reload-docs`로 언제든 수동 실행할 수 있다.
