### 🔴 이 검사들이 **구조적으로 못 보는 것** — 두 곳을 대조하지 않는다 (2026-09-07)

공통서버가 자기 가드 70개에서 같은 구멍을 찾아 알려줬고(*목록은 `[_dv_public]`를 거르는데
KPI는 안 거른다 — 두 검사 다 통과한다*), **조각도 같은 모양인지 실제로 세어봤다.**

| 우리 대조형 검사가 하는 일 | 어디 |
|---|---|
| **왕복** — 한 계산과 그 역함수를 맞춘다 | `check:i18n-roundtrip`(UTF-8·매니페스트) · `check:backup-crypto`(KAT) |
| **환경 간** — 같은 계산을 지역·언어별로 돌려 같은지 본다 | `check:timezone`(7지역) · `check:i18n`(15언어) |
| 🔴 **경로 간** — 두 코드 경로가 같은 사실에 같은 답을 내는가 | **1개**(2026-09-07 신설) — `verify:regenerate`의 *라우트 집계 == 원장 독립 집계* |
| **문서 대조** — 문서에 박힌 수와 실제 수 | `check:doc-counts` |

🔴 2026-09-07까지 세 번째 칸이 **0개**였다. 앞의 둘로는 원리적으로 못 잡는다 — 공통서버가 정리해 준 한 문장이 이유를 다 설명한다:

> **앞의 둘은 한 계산을 여러 입력으로 돌리고, 빠진 셋째는 두 계산을 한 입력으로 돌린다.**

그래서 2026-09-07의 원가 누락(`AI_REPORT_SYSTEM` §6.6.1)이 `verify:regenerate` 11개와
`check:admin` 30개를 **둘 다 통과한 채로** 살아 있었다 — 각자 자기 화면만 봤기 때문이다.
⚠ 이름을 공통서버와 **같게 맞췄다**(왕복 / 환경 간 / 경로 간) — 두 레포가 같은 결함을
  다른 말로 부르면 다음에 같은 것인 줄 못 알아본다.

⚠ **개수 축으로는 안 잡힌다.** `check:doc-counts`가 세는 것은 *검사가 몇 개인가*이고,
허위 오라클(파괴 테스트)이 잡는 것은 *그 검사가 아무것도 안 보는가*다. 이건 셋 다 아니다 —
**검사는 진짜고 각자 옳은데, 둘을 이어 보는 사람이 없다.**

✅ **그 결함을 고치면서 첫 경로 간 검사를 세웠다**(같은 날). 옛 코드로 되돌리면 이렇게 운다 —
`라우트 1/0/0 vs 원장 2/3000/300`. **호출 2회·3,300토큰이 1회·0토큰으로 보이던 것**이다.
⚠ 하나가 생겼을 뿐이다. 나머지 자리는 여전히 비어 있다.

⚠ 그리고 이 목록에 `check:timezone`이 있는 것이 우연이 아니다 — 그 가드는 2026-09-02에
**자기가 지역 수를 단언 수로 세고 있어서** 단언을 전부 지워도 초록불이었다. 대조를 하려면
**대조하는 쪽도 대조당해야 한다.**

**가져온 규약**(공통서버 `CLAUDE.md`): *뱃지·대시보드·기본 필터는 같은 정의를 쓴다.*
🔴 다만 그쪽이 덧붙인 경고를 함께 적는다 — **그 규약은 스스로 지켜지지 않는다.**
그쪽은 그 문장을 적어놓고도 깨진 채였다. **적어두는 것과 대조하는 검사를 두는 것은 별개의 일이다.**

#### 🔴 `.env.local` 이 **운영 DB** 를 가리킨다 — 가드를 세웠다 (2026-09-07)

위 절차는 **로컬 도커 스택**을 전제로 적혀 있는데, `server/.env.local` 의 `DATABASE_URL` 은
2026-09-04 운영 프로젝트 신설 검증 때 그쪽을 향해 두고 **안 되돌렸다.** 그래서 그때까지
`npm run db:push` 한 번이면 **사용자가 쓰는 스키마가 바뀌고**, `e2e:ai`·`verify:*` 가 운영 DB에 썼다.

⚠ **아는 사람이 있었는데 막지는 않고 있었다** — `verify-hierarchy.mjs` 주석이
*"`DATABASE_URL` 이 원격을 가리켜서 이 스크립트가 만든 행은 **테스터가 쓰는 DB** 에 남는다"* 고
경고만 했다. **주석은 다음 사람을 막지 못한다.**

```bash
# 원격을 향하면 넷 다 죽는다 — db:push · e2e:ai · verify:regenerate · verify:hierarchy
npm run db:push
#   db:push 가 원격 DB를 향한다 — aws-0-ap-northeast-2.pooler…

# 평소 (로컬)
DATABASE_URL="postgresql://postgres:postgres@127.0.0.1:54422/postgres" npm run db:push

# 정말 운영에 해야 할 때만 — 배포 시 스키마 적용 등
ALLOW_REMOTE_DB=1 npm run db:push
```

🚫 **로컬로 폴백하지 않는다.** `drizzle.config.ts` 가 남긴 교훈이다 — 엉뚱한 DB를 보고
*"변경 없음"* 이라고 말하는 것이 가장 나쁜 실패다. 원격이면 **소리 내어 죽고** 손을 한 번 더 쓰게 한다.
⚠ 가드는 `.env.local` 을 **안 고친다** — 그 파일이 무엇을 가리켜야 하는지는 별개의 결정이다.
🔴 **기준은 "원격인가"가 아니라 "원격에 쓰는가"다.** `peek-reports.mjs`(읽기 전용)에는 일부러
안 걸었다 — 운영 리포트를 여는 것이 그 도구의 존재 이유이고(문의 답변), 묶으면 **CS 경로가 막힌다.**

⚠ 기본 포트(5432x)를 다른 프로젝트의 Supabase 스택이 쓰고 있어 **544xx로 옮겼다.**
자세한 것은 [`BACKUP_SYSTEM.md`](./BACKUP_SYSTEM.md) §7.

## 4. 아키텍처 원칙

- 의존 방향: `app/`(라우트) → `features/` → `db/`·`lib/`·`store/`·`types/`. 역방향 import 금지.
- **일기의 진실은 기기 로컬**이다. 서버는 **읽을 수 없는** 백업 사본을 갖는다. 서버가 죽어도 앱은 동작해야 한다.
- **서버는 일기를 저장하지 않는다.** 백업은 암호문, AI 프록시는 무저장 — "저장하지 않습니다"(O) / "볼 수 없습니다"(X).
- **공통 기능은 common_server, 조각 도메인은 조각 서버.** 상세는 [`ARCHITECTURE.md`](./ARCHITECTURE.md).
- **신원은 common_server가 단일 진실.** 조각은 자체 로그인을 만들지 않는다.
- 공통 UI는 `components/`에만. Atomic Design 쓰지 않는다.
- `any` 금지, `strict` 유지.
- `server/`는 Metro 번들 대상이 아니다(`metro.config.js` blockList).
