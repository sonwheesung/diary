# 조각 — 운영 콘솔 (조각 서버)

> 조각 서버(`server/`)의 관리자 화면. **배구명가 `/ops-9f3a2c`를 승계**하되 도메인이 다른 탭은 뺀다.
> 문의·공지·구독·신원은 **common_server 콘솔(`/ops-4b7e21`)이 이미 갖고 있다** — 여기서 다시 만들지 않는다.
> 서버 경계는 [`ARCHITECTURE.md`](./ARCHITECTURE.md), 백업은 [`BACKUP_SYSTEM.md`](./BACKUP_SYSTEM.md),
> AI는 [`AI_REPORT_SYSTEM.md`](./AI_REPORT_SYSTEM.md).

---

## 1. 한 줄 요약

**조각 서버는 원격 관측이 0이었다.** 테이블 6개에 무엇이 쌓이는지 볼 방법이 없었다.
이 콘솔은 **읽기 전용 관측**이다 — 집계만 보여주고, 아무것도 바꾸지 않는다.

가장 급한 것은 `ai_usage`다. `CLAUDE.md` §7.2가 *"AI는 원가 실측 전까지 월간·연간으로
확대하지 않는다"* 라고 해놨는데 **실측할 화면이 없었다.**

## 2. 배구 콘솔에서 무엇을 가져오고 무엇을 뺐나

배구는 19탭이다. 조각은 **4탭**이다. 뺀 것이 대부분인데, 게을러서가 아니라
**데이터가 없거나 다른 서버에 있기 때문**이다.

### 가져온 것 (구조·규약)

| | |
|---|---|
| URL이 `/admin`이 아니다 | `/ops-7c1d94` — 추측 차단. **실제 보안은 토큰**이고 URL은 소음 감소용이다 |
| `ADMIN_TOKEN` Bearer + **fail-closed** | 토큰이 없거나 16자 미만이면 **전면 거부**. 크론의 fail-open을 복제하지 않는다 |
| 상수시간 비교(`timingSafeEqual`) | 길이가 다르면 즉시 false — `timingSafeEqual`이 동일 길이를 요구한다 |
| 외부 스크립트·스타일 0 | 인라인 `<style>` 문자열 하나. XSS 표면을 최소로 둔다 |
| `localStorage`에 토큰, 부팅 시 재검증 | 401이면 로그인 화면으로 되돌린다 |
| 네트워크 실패를 `status: 0`으로 정규화 | 안 하면 fetch가 throw해 **버튼이 영구 로딩에 갇힌다** |

### 뺀 것과 그 이유

| 배구 탭 | 왜 뺐나 |
|---|---|
| 사용자 현황 · 리텐션 | **신원이 common_server에 있다.** 조각 서버는 `subject_id`만 알고 이메일도 모른다. 게다가 조각은 로컬 우선이라 **앱을 켠 것을 서버가 모른다** — DAU를 셀 재료가 없다 |
| 플레이 · 전지훈련 · 경기 · 선수 · 업적 | 게임 도메인 |
| 행동 텔레메트리 | 조각은 **수집하지 않기로 했다.** 없는 것을 빈 탭으로 만들지 않는다 |
| BM · 수익화 | 엔타이틀먼트가 common_server(Phase 9) |
| 광고 | AdMob 대시보드가 정본이다. 우리가 다시 그릴 이유가 없다 |
| **오류 모니터링** | `server/lib/observability.ts`의 `reportError`가 **콘솔 출력뿐**이다. 오류 테이블이 없어 보여줄 데이터가 0이다. ⏭ Sentry를 붙이는 날 이 탭이 생긴다 |
| 쿠폰 · 우편 | 없는 기능 |
| 공지 · 패치노트 · 개발자노트 · **문의** | **common_server 콘솔이 갖는다.** 특히 문의는 그쪽이 답변까지 처리하고, 회원 문의일 때 *"앱의 '내 문의 내역'에 그대로 노출됩니다"* 경고까지 붙어 있다 |
| 운영 설정 | 조각 서버에 설정 테이블이 없다. 정책은 `lib/ai-policy.ts`·`lib/policy.ts`의 **코드 상수**이고, 그게 의도다(§5) |

### 남은 5탭

```
대시보드      한눈에 — 금고 · 저장 · 이번 달 AI · 치울 것
AI 사용량     주 · 월 · 연 집계 + 일별 추이 + 모델별 원가
리포트 품질   생성된 요약문 열람 (2026-08-13 추가)              ← 프롬프트를 고칠 근거
백업 금고     금고 · 세대 · blob · 파기 예정
정리          리퍼가 다음에 치울 것들 (쌓이면 크론이 안 도는 것이다)
```

#### 🔴 리포트 품질 탭만은 §3의 예외로 **보이지만 아니다**

이 탭은 사용자가 쓴 일기를 바탕으로 만들어진 **요약문을 그대로 읽는다.** §3(개인 비특정)과
충돌하는 것처럼 보이지만, 지키는 방식은 같다:

| | |
|---|---|
| 라우트가 `subject_id`를 **select하지 않는다** | 응답에 없으면 화면이 그릴 수 없다 |
| 정렬·필터에도 안 쓴다 | 신고 여부·`concern`·시각만으로 충분하다 |
| 결과 | 요약문은 읽되 **누가 썼는지는 못 안다** |

⚠ 그래서 이 화면으로 할 수 있는 것은 *"이 프롬프트가 이런 글을 쓴다"* 까지이고,
*"이 사람은 이런 일기를 쓴다"* 는 만들어지지 않는다. 그 선을 넘는 코드를 여기 추가하지 않는다.

⚠ **신고된 것이 먼저 온다.** 정상 리포트 1,000건보다 *"이건 이상하다"* 5건이
   프롬프트를 고치는 데 훨씬 직접적이다.

## 3. 🔴 조각만의 규칙 — **개인을 특정할 수 있게 만들지 않는다**

배구 콘솔에는 `사용자 현황` 탭이 있어 유저를 개별로 본다. **조각은 그러면 안 된다.**

조각은 E2EE 제품이다. 서버는 일기를 못 읽는데, 콘솔이 `subject_id` 목록을 보여주면
운영자가 **common_server 콘솔의 `subjects`(이메일)와 맞춰볼 수 있다** — 그러면
*"누가 언제 백업했고 AI를 몇 번 썼는가"* 가 만들어진다. 본문을 못 읽는 것과 별개로,
그건 우리가 갖지 않기로 한 정보다.

| 지킬 것 | 방법 |
|---|---|
| **`subject_id`를 화면에 내리지 않는다** | 라우트가 아예 select하지 않는다. 응답에 없으면 실수로 그릴 수도 없다 |
| 개별 행 목록을 만들지 않는다 | 전부 `count`·`sum`·`avg`. 배구의 사용자 테이블에 해당하는 화면이 없다 |
| 분포는 **버킷으로** | "금고당 blob 수"는 목록이 아니라 히스토그램이다 |

⚠ 이 규칙을 깨는 순간 §5의 *"조각 침해 = 전 앱 신원 유출"* 이 **콘솔에서도** 성립한다.
  DB 키가 아니라 화면으로 새는 경로가 하나 더 생기는 것이다.

## 3.5 ⚠ 빌드와 dev 서버가 같은 `.next`를 쓴다 (2026-08-13에 겪음)

`npm run dev`가 떠 있는 상태에서 `npm run build`를 돌리면 **dev 서버의 `.next`가 깨진다** —
콘솔 페이지가 `MODULE_NOT_FOUND`로 500을 낸다. 코드 문제로 오해하기 쉽다.

→ 고치는 법: dev를 멈추고 `rm -rf .next` 후 다시 띄운다.
→ 피하는 법: **빌드 검증은 dev를 끄고 한다.**

## 4. 읽기 전용이다 (v1)

배구 콘솔은 쿠폰 발급·환불·우편 등 **쓰기**가 많다. 조각 콘솔은 **아무것도 바꾸지 않는다.**

그래서 `ADMIN_TOKEN`이 새도 피해가 *"관측 집계가 노출됐다"* 로 끝난다 — 금고를 지우거나
권한을 주거나 남의 백업을 건드릴 수 있는 버튼이 **존재하지 않는다.**

⏭ 나중에 쓰기가 필요해지면(예: 리퍼 수동 실행) **그때 이 문단을 고치고** 추가한다.
   지금 "혹시 몰라서" 넣지 않는다.

## 5. 정책은 화면이 아니라 **코드 상수**다

배구에는 `운영 설정` 탭이 있어 서버 정책을 화면에서 바꾼다. 조각은 안 한다.

`WEEKLY_PER_WEEK`·`DAILY_CALL_CAP`·`MAX_INPUT_CHARS`는 `server/lib/ai-policy.ts`에 있고,
**앱 문구와 짝이 맞아야 한다**(화면에는 "주에 한 번"이라 적어놓고 서버가 두 번을 허용하면
사용자는 그걸 버그로 겪는다). 화면에서 바꿀 수 있게 하면 그 짝이 **배포 없이 깨진다.**

→ 콘솔은 **지금 값이 무엇인지 보여주기만** 한다. 바꾸려면 커밋해야 한다.

---

## 6. 원가는 **추정치라고 적는다**

AI 탭이 원가를 보여주지만, 그건 `input_tokens`·`output_tokens`에 단가를 곱한 값이다.

⚠ **청구서가 아니다.** 캐시 할인·배치 할인·단가 개정이 반영되지 않고, 실패한 호출은
  애초에 행이 없다(성공만 기록한다). 벤더 대시보드가 정본이고 이 숫자는 **추세를 보는 용도**다.

단가는 `server/lib/ai-policy.ts`가 아니라 `lib/admin-pricing.ts`에 둔다 — 정책(캡)과
가격(변한다)은 성질이 다르고, 가격이 바뀌었다고 캡 파일을 건드리게 하면 안 된다.

## 7. 검증

```bash
cd server
npm run typecheck
npm run build            # 콘솔이 클라이언트 컴포넌트라 빌드가 실제 검사다
npm run e2e:admin        # 인가 게이트 — 토큰 없음 · 틀림 · 미설정(fail-closed)
```

⚠ **`ADMIN_TOKEN` 미설정 상태를 반드시 검사한다.** fail-open으로 잘못 짜면 그 순간
  콘솔이 전 세계에 열린다 — 배구가 크론에서 겪고 §13.15에 남긴 교훈이다.
