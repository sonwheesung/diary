## 1. 연령 게이트 (2026-08-27)

### 1.1 왜 지금 만드나 — 고지가 코드를 앞질렀다

처리방침 §2가 **현재형으로** 이렇게 적어 15개 언어와 공개 웹페이지에 나가 있다:

> ※ 만 14세 미만 아동은 로그인 기능을 이용할 수 없습니다.

그런데 `signIn()`은 곧장 `GoogleSignin.signIn()`을 부르고, **연령 문자열이 `locales/*.json`에 0개**였다.
확인도 차단도 없다 — 배구명가가 걸렸던 체크박스형보다 **한 칸 앞이다. 묻지도 않았다.**

`CLAUDE.md` §12(2026-08-24) *"고지가 코드를 앞질렀다"*(AI 파기)와 **같은 종류**다. 그때와 같은 처방을 쓴다 —
**문장을 무르지 않고 코드를 채운다.** 무르는 쪽이 쉽지만, 그건 우리가 한 약속을 사용자 모르게 되가져가는 일이다.

### 1.2 🔴 게이트를 **부팅**으로 옮겼다 — 2026-09-01에 뒤집었다

> **아래 1.2-옛은 2026-08-27부터 2026-09-01까지 유효했던 결정이다.** 근거가 틀려서 뒤집은 것이
> 아니라 — 그 근거는 그때 맞았다 — **전제가 코드 변경으로 사라졌다.** 지운 자리를 남겨두는 이유는
> 같은 논증이 다시 나올 때 *"왜 그때는 됐고 지금은 안 되는가"* 가 여기 있어야 하기 때문이다.

#### 무엇이 전제를 깼나

비로그인 사용자의 활성 지표(DAU)를 잡기로 하면서 **부팅에 기기 UUID를 발급**하게 됐다
(`POST /v1/devices` → `subjects` 행 + 활성 일자 400일 보관, `docs/SUPPORT_SYSTEM.md` §3.1).

1.2-옛의 논증은 *"§3.1이 진짜로 요구하는 것은 미달자의 **소셜 식별자**를 받기 전에 돌려보내라이고,
순서가 아니라 **경계**가 조건"* 이었다. 그 경계가 `signIn()`이었기 때문에 로그인 지점이 답이었다.

**이제 경계가 부팅이다.** 나이를 묻기 전에 우리 `subjects` 테이블에 행이 생긴다 —
광고 식별자는 Google로 가지만 이것은 **우리가 처리자**이고, 하필 이 게이트가 인용하는 조항이
**개인정보보호법 §22조의2**(만 14세 미만 법정대리인 동의)다. 경계가 옮겨갔으니 게이트도 옮긴다.

⚠ 이건 2026-08-24(AI 파기)·2026-08-27(연령 게이트)과 **같은 종류**다. 그때는 **고지가 코드를
앞질러** 거짓이 됐고, 이번은 **코드가 근거를 무너뜨린다.** 방향이 반대일 뿐 병은 같다 —
*결정의 근거는 그 결정과 함께 늙는다.*

#### 🔴 부팅 게이트지만 **벽이 아니다**

여기가 공용 §3.1 그림과 갈리는 지점이고, 반드시 지킨다.

```
실행 → [연령 게이트] ─통과→ 기기 세션 발급 · 로그인 가능 · 일기
                     └미달→ 기기 세션 발급 안 함 · 로그인 막힘 · **일기는 그대로**
```

§4가 *"미달자도 일기는 그대로 쓴다 — 막히는 것은 로그인이 필요한 기능뿐이고 **그게 우리가 게시한
문장이다**"* 를 15개 언어와 공개 웹에 내보냈다. 부팅 게이트를 벽으로 만들면 그 문장이 거짓이 되고,
기둥 3(*"내 기록은 내 기기에"*)도 함께 깨진다 — 서버에 아무것도 안 보내는 사람을 서버 지표 때문에
자기 일기에서 잠그는 셈이다.

→ 미달 판정이 하는 일은 **딱 둘**이다: ① `registerDevice()`를 부르지 않는다 ② `signIn()`을 막는다.
   화면은 안내를 보여주고 **닫으면 홈으로 간다.**

#### 미달을 저장하나 — **1년짜리 유예로 저장한다** (닫음은 저장하지 않는다)

매 부팅마다 묻는 것은 미달자를 괴롭히고, 영구히 저장하면 **나이를 먹어도 영영 막힌다.**
생년을 저장하는 것은 §1.4(공용 §3.3)가 금지한다.

→ `{ declinedAt, threshold, version }`을 저장하고 **365일 뒤에 다시 묻는다.**
  우리가 받은 것이 **연도**뿐이라 1년이 정확히 그 해상도다 — 그보다 자주 물으면 답이 같고,
  그보다 늦게 물으면 자격을 얻은 사람을 그만큼 더 막는다.
  `threshold`나 `version`이 바뀌면 유예와 무관하게 다시 묻는다(§1.5와 같은 규약).

#### 기둥 1이 지는 값을 정확히 적는다

**첫 실행에 질문이 하나 는다.** 기둥 1(*"쓰기 마찰 최소화"*)이 지는 것은 사실이고,
2026-08-27이 *"이 앱에서 가장 비싼 마찰"* 이라며 거부했던 바로 그 비용이다. 그때와 달라진 것은
**대가가 아니라 대안**이다 — 그때는 안 물어도 됐고 지금은 물어야 한다.

줄일 수 있는 만큼만 줄인다: **1회성이고**(통과 기록이 기기에 남는다), **벽이 아니고**(닫아도 일기는
쓴다), **잠금보다 먼저**다(잠금은 매 실행이고 게이트는 평생 1회라, 순서를 뒤집으면 첫 실행에
잠금을 만들자마자 게이트를 또 만난다).

### 1.2-옛 (2026-08-27 ~ 2026-09-01) — 조각은 게이트를 **부팅이 아니라 로그인 지점**에 세운다

공용 문서 §3.1은 *"로그인보다 **먼저** 둔다"* 이고, 그림은 `실행 → 게이트 → 로그인 → 앱`이다.
Delvewarden·배구명가가 그 모양인 이유는 **그 앱들이 로그인 필수**라 부팅 게이트 = 로그인 앞이기 때문이다.

**조각은 다르다.** 기둥 1이 *"로그인 없이도 일기를 쓸 수 있어야 한다"* 이고 §4가 로그인을
문의·구독·백업·AI에서만 요구한다. 부팅에 세우면 **일기만 쓰는 사람에게 나이를 묻게 되고**,
그건 이 앱에서 가장 비싼 마찰이다.

```
조각:  실행 → 홈 → 일기 (게이트 없음)
                  └→ [로그인이 필요한 지점] → [연령 게이트] → 구글 SDK → …
                                                  ↓ 미달
                                            [안내 화면] (출구 2개)
```

§3.1이 진짜로 요구하는 것은 *"미달자의 소셜 식별자를 받기 전에 돌려보내라"* 이고,
**로그인 버튼을 누른 직후에 세워도 그 요구는 그대로 충족된다.** 순서가 아니라 **경계**가 조건이다.

- 🔴 그래서 게이트는 **`useSupportAuth().signIn()` 안**에 있다. 호출처(`app/subscribe.tsx`·`app/support.tsx`)에
  맡기지 않는다 — 세 번째 호출처가 생기는 날 그 사람은 게이트를 모른다.
  §5.1의 *"구조가 보장하게 만든다"* 와 `adsEnabled()` 한 곳을 거치게 한 것과 같은 규약이다.
- `GoogleSignin.configure()`는 모듈 로드 시점에 이미 돌지만 **식별자를 만들지 않는다.**
  경계는 `signIn()`이고 게이트는 그 앞이다(공용 §5 *"SDK를 띄우지도 않는다"*).

⚠ **광고는 이 게이트가 담당하지 않는다.** 로그인을 안 한 사람도 광고를 본다.
형제 앱(LinkMemo·Idea Vault)과 같은 위치다 — 광고 개인화 동의는 UMP가, 대상 연령은 **Play 타겟층 13+ 선언**이 맡는다.
조각의 게시된 약속이 *"로그인 기능"* 에 한정돼 있어 **게이트의 범위와 문장이 정확히 일치한다.**

> ⏭ **광고 문단은 지금도 유효하다.** 게이트가 부팅으로 올라갔어도 담당 범위에 광고가 들어오지
> 않는다 — 광고 식별자는 Google이 받고 우리 `subjects`에 행을 만들지 않는다. 옮긴 이유는
> **우리가 처리자가 되는 식별자**가 부팅에 생겼기 때문이지 광고 때문이 아니다.
>
> 🔴 반대로 *"게시된 약속과 범위가 정확히 일치한다"* 는 **더 이상 참이 아니다.** 게이트가
> 이제 기기 세션도 가르므로 범위가 *"로그인 기능"* 보다 넓다. 처리방침 §2의 문장을
> 그에 맞춰 고친다(§1.8 참조).

### 1.3 판정 — 지역별 16 / 14 / 13, 판정 불가는 16

공용 문서 §2를 그대로 따르고, 배구명가가 이탈한 한 곳(**판정 불가 시 최보수 16**)도 함께 가져온다.

| 지역 | 기준 | 근거 |
|---|---|---|
| EEA + 영국 + 스위스 | **16** | GDPR §8(회원국 하향 하한 13) — 16이면 어디서도 안전 |
| 한국 | **14** | 개인정보보호법 §22조의2 |
| 미국 | **13** | COPPA |
| 그 외 | **13** | 보수적 기본값 |
| **판정 불가** | **16** | 로케일 읽기는 실패할 수 있다. **실패가 가장 느슨한 기준으로 떨어지면 게이트가 무의미해진다** |

⚠ **조각은 EEA 배포를 뺐는데도 EEA 기준을 넣는다.** 배포 국가는 언제든 넓히고(§9.1 ⏭ UMP),
로케일은 배포 국가와 무관하게 EEA로 읽힐 수 있다(해외 거주자·기기 설정). 게이트가 배포 설정에 의존하면
설정을 넓히는 날 조용히 뚫린다.

**판정식은 보수적으로**: `올해 − 출생연도 >= 기준 + 1`.
연도만 받으면 실나이가 최대 12개월 흔들려, 관대식은 기준 미달자를 들여보내 **위법**이 된다.
보수식의 대가는 자격자가 최대 11개월 늦게 들어오는 것뿐이다. **월·일을 더 묻지 않는다** — 그건 수집을 늘리는 쪽이다.

### 1.4 무엇을 저장하나 — 생년은 저장하지 않는다

```ts
{ passedAt, threshold, version }   // 저장한다
{ birthYear }                      // 받아서 판정하고 버린다
```

- 🔴 `makeRecord(threshold, now)` 는 **생년을 인자로도 받지 않는다.** 실수로 같이 저장되는 경로를
  타입 수준에서 없앤다 — 주석으로 금지하는 것보다 강하다.
- 🔴 **서버로 아무것도 보내지 않는다.** 배구명가는 가입 시 `ageConfirmed` 불리언을 보내지만, 조각의
  신원 서버는 common_server(**수정 금지**)이고 그 계약에 이 필드가 없다. 그리고 공용 §3.3이
  *"서버는 이 값을 신뢰하지 않는다 — 법적 방어의 핵심은 중립 화면을 성실히 제공했다는 사실"* 이라
  **안 보내도 방어가 약해지지 않는다.** 보내면 수집 항목만 는다.
  → **Play 데이터 보안 선언을 건드리지 않는다.** 나가는 것이 없다.

### 1.5 재확인 트리거 — 그리고 조각에만 있는 네 번째

| 트리거 | 조각에서 |
|---|---|
| 새 설치 | 기록이 없다 |
| 규칙 버전 상승(`AGE_GATE_VERSION`) | 기준·판정식을 바꾸면 옛 통과는 근거가 다르다 |
| 🔴 **로그아웃·탈퇴** | **다시 묻지 않는다.** 연령은 사람의 속성이지 계정의 속성이 아니고, 지우면 **탈퇴가 게이트 재시도 경로**가 된다. 실측 확인: `deleteAccount()`는 `app_settings`를 건드리지 않는다 |
| **앱 초기화**(조각 고유) | **다시 묻는다.** `reset-app.ts`가 `DELETE FROM app_settings` 한다 |

**초기화에서 다시 묻는 것을 막지 않는 이유** — 세 가지가 같은 방향을 가리킨다:
① 공용 §4가 **새 설치**를 재확인 트리거로 이미 인정하고, 초기화는 재설치와 성격이 같다.
② 초기화 문구가 *"전부 지운다"* 고 약속한다 — 몰래 남기면 그 약속이 거짓이 된다.
③ 우회 대가가 **일기 전량 삭제**라 유인이 없다. 같은 대가는 앱 삭제로도 치를 수 있어 막아도 못 막는다.

→ 그래서 기록은 **`app_settings`** 에 둔다(SecureStore가 아니다). 초기화의 사정권 안에 있는 것이 옳다.

### 1.6 미달 화면 — 출구 둘, 재입력 없음

- 문의 경로와 처리방침 링크를 둔다(공용 §3.5). **버튼 없는 막다른 화면을 만들지 않는다.**
- 🔴 같은 세션에서 **다시 입력할 수 없다.** *"다른 계정으로"* 같은 대안도 제시하지 않는다(공용 §5).
- ⚠ 미달자도 **일기는 그대로 쓴다.** 막히는 것은 로그인이 필요한 기능뿐이고, 그게 우리가 게시한 문장이다.

### 1.7 파일 배치

| 무엇 | 어디 |
|---|---|
| **순수 판정** — 지역표·기준·보수 판정식·버전·기록 | `features/auth/age-gate.ts` — RN·저장소·네트워크 import 0 |
| 기기 계층 — 지역 읽기(`expo-localization`)·기록 저장 | `features/auth/api/age-store.ts` |
| 화면 — 중립 연도 선택 + 미달 안내 | `features/auth/components/AgeGateScreen.tsx` |
| 배선 | `features/support/auth-gate.ts` `signIn()` **맨 앞** |
| 회귀 가드 | `npm run check:age-gate` — 지역 × 출생연도 경계 전수 |

**순수 계층을 떼는 이유**는 AI(`features/ai/`)와 같다 — 네이티브를 모르면 가드가 그 파일을 그대로
컴파일해 **경계값을 전수로** 잴 수 있다. 화면을 띄워야만 확인되는 규칙은 결국 확인되지 않는다.

### 1.8 ⚠ 처리방침 문장과의 관계 — 고치지 않는다

처리방침은 *"만 **14세** 미만 아동은 로그인 기능을 이용할 수 없습니다"* 라고 적었고, 게이트는 지역에 따라
**16·14·13**을 쓴다. 어긋난 것처럼 보이지만 **문장은 그대로 참이다**:

- 한국 사용자에게 기준은 정확히 14다 — 그 문장이 겨냥한 독자다(한국어 정본).
- EEA(16)는 **더 엄격**하다. *"14세 미만은 못 쓴다"* 는 약속을 더 강하게 지키는 것이지 어기는 것이 아니다.
- 미국(13)은 더 느슨하지만, 그 지역에서 우리를 구속하는 것은 COPPA(13)이고 한국어 처리방침의
  §22조의2 서술은 **한국 이용자에 대한 진술**이다.

⚠ 하나 남는 긴장: 보수 판정식 때문에 **생일이 지난 만 14세가 최대 11개월 막힌다.**
문장은 *"14세 미만은 못 쓴다"* 이지 *"14세면 반드시 쓸 수 있다"* 가 아니라 거짓은 아니지만,
**막힌 당사자에게는 그렇게 안 읽힌다.** 그래서 미달 화면이 *"일기는 그대로 쓸 수 있어요"* 를
반드시 함께 말한다(§1.6) — 이 문장이 그 긴장을 실제로 감당하는 유일한 장치다.

### 1.9 에뮬레이터 실동작 확인 (2026-08-27 · `diary` AVD · en-US 로케일 → 기준 13)

순수 계층이 못 보는 것만 골라 눈으로 봤다. **여섯 가지 전부 통과.**

| 확인한 것 | 결과 |
|---|---|
| 로그인 지점에서 게이트가 뜬다 | ✅ 설정 → 문의하기 → *Sign in and continue* → 연도 목록 |
| **중립** 입력이다 | ✅ *"What year were you born?"* + 연도 목록. 체크박스 아님 |
| 미달 → 안내 화면 | ✅ *"Signing in is available from age **13**"* — 로케일에서 유도한 기준이 문구에 그대로 |
| 미달자에게 **아무것도 저장 안 한다** | ✅ 앱을 다시 띄우면 **다시 묻는다**(기록이 없다) |
| **같은 세션 재입력 차단** | ✅ 미달 뒤 다시 로그인을 눌러도 연도 목록이 아니라 **곧장 안내 화면** |
| 통과 → 기록 저장 · 재확인 없음 | ✅ 아래 |

**저장된 값**(`run-as` + `sqlite3` 로 기기 DB 직접 조회):

```
age_pass = {"passedAt":1787799174929,"threshold":13,"version":1}
```

🔴 **생년이 없다** — 고른 값(`1912`)으로 `app_settings` 를 검색해 **0건**을 확인했다.
그리고 통과 뒤 **구독 화면의 로그인 버튼**(두 번째 호출처)을 눌렀을 때 게이트가 **뜨지 않았다** —
기록을 존중한다는 것과 **배선이 호출처가 아니라 `signIn()` 안에 있다**는 것이 한 번에 확인된다.

⏭ **못 본 것**: EEA(16)·한국(14) 기준의 화면 문구는 로케일을 바꿔야 보인다(판정 자체는 가드가 전수로 잰다).
`AGE_GATE_VERSION` 상승 시 재확인도 아직 실측 전이다 — 올릴 일이 생길 때 함께 본다.
