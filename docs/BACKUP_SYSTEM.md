## 1. 한 줄 요약

일기를 **기기에서 잠근 뒤** 서버에 올린다. 서버는 암호문과 메타데이터를 **저장하지만 읽지 못한다.**

```
로컬 DB → 매니페스트 → 파트 분할 → 봉인 → reserve → 서명 URL PUT → commit
로컬 DB ← 전체 교체  ← 병합    ← 개봉 ← 다운로드 ← 서명 URL     ← latest
```

### ⚠ 고지 문구 — AI와 정반대다

| | 정확한 표현 | 쓰면 안 되는 표현 |
|---|---|---|
| **백업** | **"우리는 읽지 못합니다"** | ~~"아무것도 저장하지 않습니다"~~ — 암호문과 메타데이터는 저장한다 |
| **AI 리포트** | **"저장하지 않습니다"** | ~~"볼 수 없습니다"~~ — 본문이 평문으로 프록시를 지나간다 |

**한 화면에 섞어 쓰지 않는다.** i18n 키도 `backup.notice.*` / `ai.notice.*`로 분리해 재사용을 막는다.

## 2. 키 — 복구 코드 하나에서 전부 유도된다

```
복구 코드 = 128비트 CSPRNG = 27자 (Crockford Base32 26심볼 + 체크심볼 1)
  ├─ DEK      = HKDF-SHA256(코드, "jogak/dek/v1",      32B)  ← XChaCha20-Poly1305 키
  ├─ vault_id = HKDF-SHA256(코드, "jogak/vault-id/v1", 16B)  ← 서버에서 금고를 찾는 이름
  └─ kid      = HKDF-SHA256(코드, "jogak/kid/v1",       4B)  ← 봉투 헤더의 키 식별자
```

**기기에 저장하는 것은 비밀 16바이트 하나뿐이다**(`jogak.backup.secret`, SecureStore).
나머지는 매번 유도한다 — 두 벌을 두면 어긋나고, 어긋나면 남의 금고를 조회하거나 못 여는 금고가 생긴다.

### 되돌릴 수 없는 결정 4개

사용자에게 발급한 값이거나 마이그레이션 경로가 없는 것들이다. **바꾸면 기존 사용자가 백업을 영영 못 연다.**

| # | 결정 | 왜 되돌릴 수 없나 |
|---|---|---|
| 1 | **코드 형식** — 128비트 · MSB-first · 하위 2비트 0 패딩 · 체크심볼 = **128비트 정수** mod 37 · 4자 6그룹 + 3자 | 종이에 적어둔 값이 앱과 달라진다 |
| 2 | **SecureStore 키 이름** `jogak.backup.secret` | SecureStore에 마이그레이션 개념이 없다 |
| 3 | **`vault_id` 표현** — 소문자 hex 32자 | DB 컬럼·서명 URL 경로·오류 코드가 전부 이 표현이다. 어긋나면 전 사용자 재업로드 |
| 4 | **HKDF info 문자열** — US-ASCII 바이트 그대로, NUL 종단·길이 접두 **없음** | 어긋나면 키가 통째로 달라지는데 **자기 왕복 테스트로는 100% 통과한다**(양쪽이 같은 코드를 쓰니까) |

### 왜 256비트가 아니라 128비트인가

256비트면 53자, 128비트면 27자다. 128비트는 무차별 대입으로 깨지지 않으므로(2^128) 실질
보안은 같고, **이 기능의 실제 실패 모드는 해독이 아니라 오타와 분실**이다. 손으로 옮겨 적는
글자 수를 절반으로 줄이는 쪽이 훨씬 크게 이긴다.

### ⚠ Extract를 건너뛸 수 없다 (설계 정정, 2026-08-11)

~~"입력이 이미 균일 랜덤이니 HKDF-Expand만 쓴다"~~ → **Extract + Expand.**
RFC 5869 §2.3이 *"PRK: a pseudorandom key of **at least HashLen** octets"* 를 요구해
16바이트 코드는 PRK 자리에 올 수 없다. "입력이 균일하다"는 **엔트로피** 얘기였고 길이 요건은
별개다 — Extract가 정확히 그 일(짧은 IKM → HashLen PRK)을 하라고 있는 단계다. salt는 비운다.

**KAT가 이걸 잡았다.** 자기 왕복만 돌렸으면 통과했을 오류이고, 다른 기기에서 복원할 때
처음 드러났을 것이다.

## 3. 봉투 v1

```
magic "JGKB" 4 | version 1 | suite 1 | flags 1 | kid 4 | type 1 | ctxLen 1 | context N | nonce 24
암호문 ‖ tag(16)
```

**헤더 전체가 그대로 AAD다.** 목적은 적대적 운영자가 아니라 **내 업로드 코드가 파일을
뒤바꾸는 사고를 소리 나게 만드는 것**이다 — 그렇게 적어두지 않으면 다음 사람이 서명 체인·
투명성 로그로 확장한다.

| 필드 | 값 | 근거 |
|---|---|---|
| `version` | `0x00~0x0F` **실험 구간**, 사용자 릴리스는 `0x10` 이상 | "초안"을 문서 표현이 아니라 **바이트로 강제**한다 |
| `suite` | `0x01` = XChaCha20-Poly1305 + HKDF-SHA256 | `0x00`은 예약이라 거부 |
| `flags` | bit0 = 키 래핑(KEK/DEK) **예약만** | ⚠ 켜는 순간 **Play E2EE 면제가 사라진다** — 키가 서버로 가는 설계라서다 |
| `ctxLen` | context 바이트 수 | 없으면 모르는 `type`에서 nonce 위치를 못 찾는다. 그래도 **모르는 type은 거부**한다 |
| `context`(manifest) | `seq u32 BE` + `genId 8B` + `part u16 BE` + `partCount u16 BE` | `seq`가 u32인 이유는 아래 |
| `context`(blob) | `sha256(암호문) 32B` | 2차(사진) |

### `genId`가 없으면 세대가 찢어진다

같은 `seq`로 재시도하는 동안 서버에 **옛 파트와 새 파트가 함께 남을 수 있다.**
`seq`도 `partCount`도 같아서 AEAD가 **전부 통과한다** — 조용한 데이터 손상이다.
세대마다 랜덤 8바이트를 헤더에 넣어 묶는다.

### `seq`가 u64가 아니라 u32인 이유

`DataView.getBigUint64`는 **BigInt**를 돌려주고, BigInt는 `JSON.stringify`가 **throw한다.**
`seq`가 매니페스트 JSON이나 오류 코드 문자열(`JGKB-E07/seq=41`)로 흐르는 순간 터진다.
42억 세대면 하루 한 번 백업해도 1100만 년이다.

### ⚠ `DataView(bytes.buffer)`는 `byteOffset`을 무시한다

다운로드한 봉투에서 `subarray`로 헤더를 떼면 `.buffer`가 원본 전체를 가리켜 오프셋이 전부
어긋난다. **0 오프셋 왕복 테스트로는 절대 안 잡힌다** — 회귀로 박아뒀다.

## 4. 매니페스트 — 무엇이 백업되는가

**앱의 `Diary` 타입을 쓰지 않는다.** 그건 뷰다 — 블록이 파싱돼 있고, 태그가 조인돼 있고,
묘비가 빠져 있다. 뷰를 실으면 셋이 조용히 사라진다:

1. 모르는 블록 타입 (`filter(isDiaryBlock)`이 걸러낸다)
2. 지운 조각의 묘비
3. **태그의 원래 순서** (`tags.created_at` — `ORDER BY`의 유일한 출처다)

그래서 저장소 계층을 우회하고 **원본 행**을 직접 읽는다.
→ ⚠ `db/migrations.ts`에 컬럼을 추가하면 `manifest-builder.ts`도 같이 고쳐야 한다.
   안 고치면 그 값이 백업에서 조용히 빠지고 **타입이 잡아주지 않는다.**

### 실어야 하는데 빠지기 쉬운 것

| 필드 | 왜 |
|---|---|
| `content` (파생 평문) | **파생인데도 싣는다.** `content_blocks`가 깨졌을 때의 유일한 중복성이다. 안 실으면 `parseBlocks`가 빈 배열을 주고 `content`가 `''`가 되어 **날짜만 있고 본문이 없는 조각**이 남는다(사용자에게는 사라진 것과 구별되지 않는다) |
| `dbVersion` | 봉투의 `version`은 **암호 형식**이라 스키마를 말해주지 않는다. 없으면 새 앱이 만든 백업을 옛 앱이 복원할 때 컬럼을 조용히 버리거나 raw SQL 오류로 죽는다 — 그것도 전부 받아 복호화한 뒤에. **더 새 스키마는 거부한다** |
| 묘비 | 본문은 비우되 행은 싣는다. ⚠ `content`·`created_at`·`updated_at`이 **NOT NULL**이라 "id·날짜·`deleted_at`만"으로 만들면 복원 INSERT가 통째로 실패한다 |
| `tags.created_at` | 태그 표시 순서의 유일한 출처 |

### 파트마다 완결된 JSON

큰 JSON 하나를 바이트로 잘라 나누면 읽는 쪽이 **전부 이어붙인 뒤에야** 파싱할 수 있어
힙 정점이 그대로다 — 나누는 이유(저사양 기기 OOM)가 사라진다.
파트마다 행을 나눠 담은 **독립 문서**로 만들고, 읽는 쪽은 배열을 이어붙이기만 한다.
목표 크기 **512KB**(⚠ 실기기 측정 전까지 추정치).

### UTF-8은 손으로 짰다 — 표준보다 관대하다

순수 계층은 임포트 0을 지켜야 해서 `TextEncoder`를 못 쓴다. 25개 스크립트로 Node `Buffer`와
**바이트 단위 대조**해 일치를 확인했다(§7).

⚠ **딱 한 곳이 표준과 다르고, 그게 의도다.** 짝 없는 서러게이트를 만나면
Node 표준은 `U+FFFD`로 **바꿔 원본을 파괴**하는데, 우리 인코더는 그대로 실어 왕복시킨다.

```
'앞\uD83D뒤'   내 것 : ec 95 9e  ed a0 bd  eb 92 a4   → 원본 복원 ✅
              Node : ec 95 9e  ef bf bd  eb 92 a4   → U+FFFD로 대체(손실)
```

백업은 **보존이 목적**이라 이쪽이 맞다. 다만 결과는 엄밀히는 WTF-8이므로, 서버나 외부 도구가
UTF-8 유효성을 검사하면 걸릴 수 있다 — 지금은 암호문 안에 있어 아무도 검사하지 않는다.

## 5. 서버 계약

### 3단 업로드

```
POST /api/v1/backup/reserve   → 서명 URL N개
PUT  <서명 URL>                → Storage에 **직접** (암호문이 우리 함수를 지나가지 않는다)
POST /api/v1/backup/commit    → 서버가 Storage에 실제 크기를 물어 대조
POST /api/v1/backup/latest    → 완성된 세대의 다운로드 URL
```

| 규칙 | 근거 |
|---|---|
| `seq`는 정확히 **+1**만 | 앞서면 구멍, 같거나 뒤면 덮어쓴다 |
| 같은 `seq`를 **다른 `genId`로** 다시 올리면 옛 파트를 지우고 시작 | 남겨두면 나중에 섞여 찢어진 세대가 된다 |
| `reserve`는 **멱등** — 재호출하면 URL 재발급 | ⚠ `createSignedUploadUrl` TTL이 **2시간 고정**이라 느린 업로드가 만료된다. 처음부터 다시 하게 만들면 느린 네트워크 사용자는 영원히 백업을 못 한다 |
| `commit`은 **앱이 보낸 크기를 믿지 않는다** | 앱 숫자로 쿼터를 세면 조작해 무한히 쓸 수 있다. ⚠ 서명 URL에 크기 제한 파라미터가 없어서 사후 대조가 유일한 수단이다 |
| 하나라도 없으면 **미완성으로 남기고 거부** | 반쪽 세대를 커밋하면 복원이 그만큼 조용히 잃는다 |
| `commit` 재호출은 **성공으로 답한다** | 응답 유실 재시도(멱등) |
| 객체 경로는 **서버가 조립한다** | 앱 문자열을 넣으면 `../`로 남의 금고에 쓸 수 있다 |
| `vault_id`를 **쿼리스트링에 넣지 않는다** | 액세스 로그에 남는다 — 조회지만 POST다 |

### 인가

| | |
|---|---|
| 신원 | common_server에 **introspect**(`/auth/me` + `/entitlements`, 60초 캐시). 토큰 서명을 검증하지 않는다 — 키를 공유하면 그 키가 두 곳에 생긴다 |
| ⚠ 호출이 **둘** | `/entitlements` 응답에 `subjectId`가 없다. 병렬로 부른다. ⏭ 상류에 한 줄 더하면 하나로 준다 |
| ⚠ 상류 장애는 **503이지 401이 아니다** | 앱 SDK가 401에서 `setSession(null,null)`로 **세션을 폐기한다**(`lib/common-server/index.ts:149`). common_server가 잠깐 느린 것으로 사용자가 로그아웃되면 안 된다 |
| ⚠ 상류가 죽고 **캐시가 있으면 만료돼도 쓴다** | 백업은 폰을 잃은 사람을 위한 기능인데 우리 상류가 느리다고 복원이 막히면 존재 이유가 없다 |
| 쓰기 | 구독 필요 |
| **읽기(복원)** | ⚠ **구독을 요구하지 않는다.** 폰 분실 → 결제수단이 그 폰에 묶여 갱신 실패 → 해지 → 새 폰에서 복원. 여기서 막으면 **폰을 잃은 사람을 위한 기능이 폰을 잃으면 잠긴다** |

### 소유권 — 최초 grant는 **선착순**

설계 초안에는 되찾기(rebind)만 있고 *"새 폰이 처음 이 금고를 잡는"* 경로가 없었다.
읽기에 grant가 필요한데 grant를 만드는 길이 rebind뿐이고 rebind는 복원 뒤에 오므로 **순환**이었다 —
주 시나리오(기기 분실 → 새 폰)가 계약상 불가능했다.

→ **grant가 없는 금고는 요청한 계정이 그대로 가진다.**
안전한 이유: `vault_id`가 복구 코드에서 유도되므로 남의 금고를 잡으려면 그 코드를 알아야 하고,
알면 어차피 오프라인에서 복호화할 수 있다. **새로 여는 문이 없다.**
반대로 `vault_id`만으로 인가하지는 않는다 — 그 값은 서버 DB·로그에 평문으로 있다.

`vault_grants.rebound_at` — 뺏긴 기기가 다음 접속 때 **왜 백업이 멈췄는지 알아야** 한다.

### ⚠ grant는 **읽기를 지키지 않는다** (2026-08-11 정정)

처음에는 읽기에도 grant를 요구했다. 그러면 **순환**이 남는다 —
읽기에 grant가 필요하고 grant를 옮기는 되찾기는 복원 뒤에 오는데, 복원이 곧 읽기다.
"최초 grant는 선착순"이 주 시나리오를 뚫어줬을 뿐, 남이 grant를 쥔 경우는 여전히 막혀 있었다.

**읽기를 연다(Bearer만).** 근거는 간단하다 — **읽기는 암호가 이미 지킨다.**
`vault_id`를 아는 사람이 얻는 것은 **못 여는 암호문**이고, 열려면 복구 코드가 필요하며,
코드가 있으면 어차피 오프라인에서 열 수 있다. grant가 존재하는 이유는 **단일 라이터**를
강제하는 것이지 열람을 막는 것이 아니다.

| 동작 | 인가 |
|---|---|
| `latest` · 다운로드 | **Bearer만** |
| `reserve` · `commit` | Bearer + grant (없으면 **선착순으로 잡는다**) |
| `rebind` | Bearer + **`auth_key`** (아래) |
| `delete` | Bearer + (grant **또는** `auth_key`) |

### 되찾기 인가 — `auth_key`를 **해시로** 보관한다

`rebind`를 Bearer만으로 열면 `vault_id`를 아는 사람이 라이터를 뺏을 수 있다.
읽지는 못하지만 **주인의 백업을 멈추고 쓰레기 세대를 올릴 수 있다** — 실질적 피해다.

```
auth_key = HKDF-SHA256(복구 코드, "jogak/auth/v1", 32B)
서버 저장 = sha256(auth_key)          ← 원본은 저장하지 않는다
```

- 금고를 처음 만들 때(첫 `reserve`) 앱이 `auth_key`를 보내고 서버는 **해시만** 남긴다.
- 되찾기·삭제는 `auth_key`를 제시한다. 서버는 해시를 대조한다.
- **서버 DB가 통째로 새도 되찾기 권한은 안 샌다** — 해시는 되돌릴 수 없다.

⚠ 대칭 비밀이라 요청 중에는 평문으로 전송·메모리 상주한다. TLS 밖으로 나가지 않고
**절대 로그에 남기지 않는다**(`lib/observability.ts` 규율). 비대칭(Ed25519)이면 이 잔여
노출도 없지만 `@noble/curves`라는 세 번째 의존성과 챌린지 엔드포인트·nonce 테이블·리퍼가
따라온다 — **해시 보관만으로 "DB 유출 ≠ 권한 유출"이라는 핵심 이득은 이미 얻는다.**
⏭ 다시 열 조건: 되찾기 남용이 실제로 보고되거나, 서버가 이미 비대칭을 쓰게 될 때.

### 리퍼 — 실패한 업로드를 치운다

| 대상 | 기준 | 왜 |
|---|---|---|
| `reserved`인 채 남은 파트 | **24시간** | 서명 URL TTL이 2시간이라 그 뒤엔 못 올린다. 그래도 24시간을 두는 건 **느린 재시도를 죽이지 않기 위해서**다 — `reserve`는 멱등이라 재발급받아 이어갈 수 있다 |
| 미완성 세대 | 파트가 전부 사라지면 함께 | 커밋되지 않은 세대는 복원 대상이 아니다 |
| 보관 세대 수 | **최근 3개** | 잘못된 복원을 되돌릴 여지. ⚠ **복원 출처 세대는 다음 성공 백업 2회까지 evict 금지** — 되돌리려는데 그게 지워져 있으면 안 된다 |

### 파기 — 유예 90일, 툼스톤 1년

구독이 끊기면 **90일 유예 후 파기**한다(`CLAUDE.md` §7.2 확정). 파기는 객체를 지우고
`vaults.purged_at`을 찍는다 — 행은 남긴다(위 툼스톤). 툼스톤은 **1년 뒤** 리퍼가 지운다.

🔴 **지킬 수 없는 약속이 하나 있다.** `CLAUDE.md` §7.2가 *"유예 만료 전 **반드시 알린다**"*
라고 적어뒀는데 **통지 채널이 없다** — 푸시 미구현, 원격 관측 0, 이메일 발송 경로 0.
남는 건 앱 내 배너뿐인데 **폰을 잃은 사람은 앱을 안 연다.**

→ 두 갈래 중 하나를 골라야 한다. **미결정이다:**
   ① 백업을 켜는 화면에 *"앱을 열지 않으시면 알림이 닿지 않을 수 있습니다"* 를 적고 90일 유지
   ② 통지 약속을 **철회**하고 `CLAUDE.md` §7.2를 고친다 — 지킬 수 없는 약속이 가장 비싸다
   (③ 복원은 영구 무료로 두고 새 백업만 중단하는 안도 §7.2 표에 있다)

### 탈퇴 → 백업 파기

common_server의 `subject_events` 아웃박스가 **선행이다**(미구현). 그게 붙기 전까지
"탈퇴하면 백업도 지웁니다"는 **자동으로 이행되지 않는다** — Play 데이터 보안 선언과
처리방침이 그걸 전제하므로, **백업을 사용자에게 열기 전에** 매듭지어야 한다.

⚠ 커서는 **처리 완료 지점**이어야 한다. 처리 전에 올리면 그 금고는 영원히 안 지워지고,
이 프로젝트에는 원격 관측이 0이라 **아무도 모른다.**

### 파기는 행을 남긴다 (툼스톤)

`vaults.purged_at`. 행을 지우면 404밖에 못 주고, **404를 받은 사용자는 자기 일기가 지워졌다는
사실을 영원히 모른다** — "서버가 이상한가 보다"로 읽는다. 410을 주려면 행이 필요하다.
⚠ 툼스톤에 `subject_id`를 남기지 않는다("탈퇴 시 지체 없이 파기"와 충돌).

## 6. 복원 = 전체 교체

병합하지 않는다. 주 시나리오(새 폰)에서는 로컬이 비어 있어 교체가 곧 정답이고, 병합 하나를
들이면 `rev`·`origin`·충돌 화면·15개 언어 문구·"백업 차단" 상태기계가 전부 따라온다.

### 그 대가 — 확인 화면이 선택이 아니라 조건이다

⚠ **진짜 다수 케이스는 "두 기기 병행 작성"이 아니라 "로컬이 비어 있지 않은데 복원"** 이다.
백업이 수동 버튼인 한 스테일은 기본값이고, 3주 전 백업 + 그 뒤 20개 작성 상태에서 복원을
누르면 20개가 사라진다.

- **차집합 D = 로컬 alive id ∖ 매니페스트 alive id**를 세고 **날짜까지** 보여준다.
  "497개가 대체됩니다"는 위험을 표현하지 못한다 — 사라지는 건 20개다.
- 🔴 **매니페스트 쪽은 반드시 alive만.** 묘비 id를 포함하면 "A 기기에서 지운 조각"이 B 기기에서
  "백업에 있음"으로 판정돼 **경고 없이 사라진다** — 이 화면이 막으려던 바로 그 손실이다.

### 테이블 분류

| 분류 | 대상 |
|---|---|
| **교체** | `diaries` · `diary_images` · `tags` · `diary_tags` |
| **보존** | `app_settings` 전체 + `backup_state` |
| **병합** | **없음** |
| **외부(건드리지 않음)** | `Paths.document/diary-images/` 파일 트리 |

- ⚠ `app_settings`를 건드리면 **언어가 날아가** 복원 직후 안내를 **못 읽는 언어로** 만난다.
- ⚠ `backup_state`가 교체 대상 안에 있으면 두 갈래로 깨진다 — 지워지면 `seq=1`을 올려 충돌하고,
  남으면 **복원 전 기기의 커서**라 역시 어긋난다. 그래서 별도 테이블이다.
- ⚠ `blob_state`를 매니페스트 값이 아니라 **`'missing'`으로 강제**한다. 1차는 사진 파일을
  안 가져오므로 원본의 `'present'`를 쓰면 "파일이 있다"고 주장하는 행이 생긴다.
- 복원의 **마지막 단계**가 커서를 복원한 세대로 맞춘다. 빠뜨리면 직후 첫 백업이 409를 받는다.

### ⚠ 외부 고정 벡터(KAT)가 왕복 테스트보다 먼저다

자기 왕복만 보면 IETF 변종을 잘못 골라도, 엔디안이 뒤집혀도, HKDF info 인코딩이 달라도
**전부 통과한다** — 양쪽이 같은 코드를 쓰기 때문이다. 그 오류는 **다른 기기에서 복원할 때**
처음 드러나고, 그때는 이미 사용자 데이터가 그 형식으로 올라가 있다.

벡터 출처(원문에서 직접 추출, 2026-08-11):
- HKDF-SHA256 — RFC 5869 Appendix A.1 / A.2 (`rfc-editor.org/rfc/rfc5869.txt`)
- XChaCha20-Poly1305 — draft-irtf-cfrg-xchacha-03 Appendix A.1

### 다국어 — 25개 스크립트 통과

한국어(옛한글·조합형 포함) · 日本語(반각 가나 포함) · 简体/繁體中文(확장 한자 U+20000↑) ·
ไทย(결합 문자) · Русский · Tiếng Việt · العربية · עברית · Deutsch · Français ·
ZWJ 이모지(👨‍👩‍👧‍👦) · 국기(지역 표시 문자) · 피부톤 수정자 · NFC/NFD · 이형자 선택자 · 수학 기호 · 혼합 스크립트

- **NFD를 NFC로 정규화하지 않는다** — 정규화하면 사용자가 쓴 글자가 다른 글자가 된다.
- 파트 경계가 **문자를 자르지 않는다**(행 단위로 나누므로 원리적으로 불가).

### 로컬 개발 스택

```
cd server
npx supabase start          # Postgres :54422 · Storage :54421 · Studio :54423 (전부 Docker)
cp .env.example .env.local  # supabase status 의 SERVICE_ROLE_KEY 붙여넣기
npm run db:push
npm run dev                 # :3200
npm run e2e
```

- ⚠ 기본 포트(5432x)를 **다른 프로젝트의 Supabase 스택이 쓰고 있어** 544xx로 옮겼다.
- ⚠ `[auth]`를 켜둔다. 조각은 자체 로그인을 만들지 않지만 로컬 스택에서는 그 서비스가
  **API 키 발급 주체**라, 끄면 `service_role` 키가 안 나와 Storage에 못 붙는다.
- ⚠ `AUTH_STUB=1`은 common_server 없이 계약만 시험할 때. **프로덕션 빌드에서는 무시된다.**
- **왜 Postgres+MinIO가 아닌가**: 가장 불확실한 항목이 *"RN이 5MB를 서명 URL에 PUT할 수 있는가"* 인데,
  MinIO의 S3 presigned URL은 `createSignedUploadUrl`과 API가 달라 **그 답이 거짓 확신이 된다.**

### ⚠ 미검증 — 실기기에서만 답이 나온다

| # | 무엇 | 왜 중요한가 |
|---|---|---|
| 1 | **RN fetch가 5MB `Uint8Array`(→`ArrayBuffer`) PUT을 보내는가** | RN은 요청 바디 변환 계층이 따로 있다. 로컬 Node 왕복은 5MB까지 통과했지만 **그게 실기기 통과를 뜻하지 않는다.** 막히면 파트 크기를 줄이거나 `expo-file-system` 업로드 경로로 바꾼다 |
| 2 | **`backupDatabaseAsync`가 열린 커넥션을 목적지로 받는가** | 이게 확인돼야 복원을 **스크래치 DB + 단일 스왑**으로 바꿀 수 있다. 지금은 라이브 DB에 직접 써서 **복원 중 앱이 죽으면 반쯤 교체된 상태가 남는다** |
| 3 | 순수 JS 암호 처리량 | 파트 크기 512KB가 추정치다 |

### ⚠ 릴리스 전 체크리스트

- [ ] **봉투 `version`을 `0x10`으로.** `0x00~0x0F`는 실험 구간이고 **내부 테스트도 사용자 릴리스다** —
      테스터는 자기 진짜 일기를 쓴다. 실험 버전으로 백업한 사람의 데이터는 동결 시점에
      못 읽는 데이터가 되고, 폰을 잃은 뒤라면 영구 손실이다.
- [ ] **13개 언어 원어민 검수.** 지금 `backup.*`은 ko·en만 실제 번역이고 나머지는 영어 자리 채우기다.
      오역이 곧 데이터 영구 손실인 문구라("지워져요"가 "저장돼요"가 되면 최악) 기계 번역을 넣지 않았다.
- [ ] 처리방침 §1·§2·§4·§6·§8·§9 개정 + Play 데이터 보안 재선언 (`CLAUDE.md` §5.1)
- [ ] `AUTH_STUB` 환경변수가 프로덕션에 없는지
