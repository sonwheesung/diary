# 알림 — 기록 리마인더

> 정책 근거는 [`CLAUDE.md`](../CLAUDE.md) §3(범위)·§7.1(권한은 빼는 쪽으로)·§9.1(다국어).
> 색인은 [`README.md`](./README.md).

---

## 1. 무엇을 만드나

**하루 한 번, 정한 시각에 "오늘 조각을 남겨보세요"를 보낸다. 그게 전부다.**

2026-08-07 결정으로 **화면만 만들고 기능은 비워뒀던** 항목이다(`CLAUDE.md` §3 7번).
설정에 토글이 있었고 그 아래 *"아직 실제 알림은 보내지 않아요"* 라고 적혀 있었다 —
정직했지만, 비공개 테스트로 41명이 동시에 앱을 켜는 시점에 그게 **첫인상**이 된다.

| | |
|---|---|
| 종류 | **로컬 알림만.** 서버 발송(FCM/푸시)은 하지 않는다 |
| 빈도 | 하루 1회 |
| 시각 | 사용자가 고른다. 기본 **21:00** |
| 요금 | **무료.** 구독과 무관하다 |
| 본문 | 고정 문구. **일기 내용을 넣지 않는다**(§4) |

### 🔴 이 기능의 전부는 "이미 쓴 사람에게 안 가는 것"이다

*"오늘 조각을 남겨보세요"* 가 **이미 오늘 쓴 사람**에게 오면, 그건 앱이 나를 안 보고 있다는
뜻이 된다. 리마인더의 가치가 거기서 음수로 뒤집힌다.

그런데 **로컬 알림은 조건부 발송이 불가능하다** — 예약해두면 앱이 죽어 있어도 OS가 그대로 쏜다.
"보낼 때 오늘 썼는지 확인"이라는 경로가 아예 없다. 그래서 **예약을 조작하는 방식**으로 푼다(§3).

---

## 2. 왜 푸시가 아니라 로컬인가

| | |
|---|---|
| 서버에 **보낼 수단이 없다** | 원격 관측 0 · 푸시 미구현 · 이메일 발송 경로 0([`BACKUP_SYSTEM.md`](./BACKUP_SYSTEM.md) §5가 같은 이유로 유예 통지 약속을 되물렸다) |
| 서버가 **보낼 근거도 없다** | 일기는 기기에 있다(기둥 3). "오늘 썼는지"를 서버가 알려면 그걸 서버에 알려야 한다 — 로컬 우선 설계를 리마인더 하나로 깨는 셈이다 |
| 기기는 **시간만 알면 된다** | 리마인더에 서버가 기여할 것이 없다 |

⚠ 그런데 `expo-notifications`는 **푸시 인프라를 함께 들고 온다.** 우리는 안 쓰므로
그쪽 권한을 걷어낸다 — §5.

⏭ 나중에 진짜 푸시가 필요해지는 곳은 리마인더가 아니라 **백업 유예 만료 통지**다
(`BACKUP_SYSTEM.md` §5). 그때 이 문서가 아니라 그쪽을 연다.

## 3. 예약 모델 — **7일 롤링 창**

반복 트리거(daily repeat) 한 건으로 잡지 **않는다.** 반복은 하나의 알림이라
*"오늘 것만 취소"* 가 불가능하고, 그러면 §1의 유일한 요구가 깨진다.

```
예약     앞으로 7일치를 개별 알림으로 잡는다.  식별자에 날짜를 담는다 → jogak-reminder-2026-08-25
저장     조각을 저장하면 그날 알림을 취소한다.
복귀     앱이 포그라운드로 오면 창을 다시 7일로 채운다(이미 있는 것은 건드리지 않는다).
```

### 왜 7일인가 — 1건은 체인이 끊긴다

"다음 1건만 예약하고 발사되면 다시 잡는다"가 더 단순해 보이지만 **틀렸다.**
알림이 울린 뒤 사용자가 **앱을 안 열면 다음 것을 잡을 주체가 없다.** 리마인더는
정확히 "앱을 안 여는 사람"을 위한 기능이라, 그 경로가 주 시나리오다.

7일이면 **일주일을 통째로 무시해도** 체인이 산다. 그 이상은 얻는 게 없다 —
그 사이 한 번이라도 열면 창이 다시 채워진다.

### 왜 "저장 시 취소"인가

발송 시점에 조건을 볼 수 없으니, **조건이 확정되는 시점(저장)에 예약을 지운다.**
방향을 뒤집은 것뿐이고, 이게 로컬 알림에서 유일하게 성립하는 방법이다.

| 상황 | 결과 |
|---|---|
| 오늘 썼다 | 오늘 알림 취소 → 안 온다 |
| 오늘 쓴 걸 지웠다 | **다시 예약하지 않는다.** 아래 참조 |
| 어제 날짜로 썼다 | 오늘 알림은 그대로 온다 — 취소는 **그 조각의 날짜**를 기준으로 한다 |

⚠ **지웠다고 되살리지 않는다.** 되살리면 "썼다 지웠다"를 반복하는 사이 알림이 오락가락하고,
무엇보다 그 시각이 이미 지났으면 되살릴 대상이 없다. 하루 안 오는 쪽이 조용해서 낫다.

## 4. 알림 본문에 **일기를 넣지 않는다**

잠금(`CLAUDE.md` §7.1)을 켠 사람의 잠금화면에 일기 한 줄이 뜨면 **잠금이 무의미하다.**
앱 스위처까지 가린(`FLAG_SECURE`) 앱이 알림으로 본문을 흘리면 앞뒤가 맞지 않는다.

- 본문은 **고정 문구**다. 조각 수·감정·제목 그 무엇도 넣지 않는다.
- 잠금을 안 켠 사람에게도 마찬가지다 — 켠 사람만 가리면 **알림 내용으로 잠금 여부가 드러난다.**

## 5. 🔴 권한 — 들어오는 것을 세고, 안 쓰는 것은 걷어낸다

`CLAUDE.md` §7.1은 *"안드로이드 권한은 **빼는 쪽으로** 관리한다"* 고 정해뒀다.
일기 앱에 안 쓰는 권한이 보이면 그 자체로 신뢰를 깎는다.

**⚠ 소스 매니페스트가 아니라 병합 결과를 본다.** `blockedPermissions`는 지우는 게 아니라
`tools:node="remove"`를 붙이므로 문자열은 그대로 남는다 — 실측 절차는 §7.1에 있다.

### 🔴 실측 — `expo-notifications` 하나가 권한을 **13개 → 37개**로 늘린다 (2026-08-21)

설치만 하고 병합 매니페스트를 재봤다. **24개가 들어왔고 우리가 쓰는 것은 3개다.**

```
# 릴리스끼리 비교한다. 디버그와 대조하면 디버그 전용 항목이 섞여 답이 오염된다(한 번 그랬다)
cd android && ANDROID_HOME=<sdk> ./gradlew processReleaseMainManifest --rerun-tasks
grep -o 'android:name="[A-Za-z0-9._]*permission[^"]*"'   app/build/intermediates/merged_manifest/release/processReleaseMainManifest/AndroidManifest.xml | sort -u
```

| 들어온 것 | 개수 | 쓰나 | 처리 |
|---|---|---|---|
| `POST_NOTIFICATIONS` | 1 | ✅ Android 13+ 런타임 권한 | 둔다 |
| `RECEIVE_BOOT_COMPLETED` | 1 | ✅ 재부팅 후 예약 생존 | 둔다 |
| **런처 배지·바로가기** (`sec`·`huawei`·`oppo`·`htc`·`sony`·`majeur`·`anddoes`·`everything.badger`·`android.launcher`·`READ_APP_BADGE`) | **20** | ❌ 배지를 안 쓴다 | **걷어낸다** |
| `com.google.android.c2dm.permission.RECEIVE` | 1 | ❌ **FCM 푸시.** 우리는 로컬 알림만 | **걷어낸다** |
| `BIND_GET_INSTALL_REFERRER_SERVICE` | 1 | 🟡 미확인 | **둔다** — 아래 |

🔴 **`INSTALL_SHORTCUT` · `UNINSTALL_SHORTCUT` · 런처 설정 읽기/쓰기가 일기 앱 권한 목록에
뜨는 것**은 §7.1이 정확히 막으려던 그림이다. 우리가 부르지도 않는 배지 라이브러리가
`expo-notifications`에 딸려 온 것뿐인데, 사용자에게는 "이 일기장이 왜 내 홈 화면을 건드리지"로 읽힌다.
→ `app.json`의 `blockedPermissions`에 **21개를 추가**했다(기존 3개 + 21 = 24).

⏭ `BIND_GET_INSTALL_REFERRER_SERVICE`는 **안 지운다.** Play 설치 유입 추적용이고 AdMob
어트리뷰션이 쓸 수 있는데, **쓰는지 확인하지 못했다.** 광고 수익에 영향이 갈 수 있는 것을
"안 쓸 것 같다"로 지우지 않는다 — 나머지 21개는 우리가 배지·푸시를 **안 쓴다는 것이 확실**해서 지웠다.

⚠ **소스 매니페스트만 보고 판단하지 않는다.** `blockedPermissions`는 지우는 게 아니라
`tools:node="remove"`를 붙이므로 문자열은 그대로 남는다 — 병합 결과를 봐야 실제로 빠졌는지 안다(§7.1).

#### 차단 후 재측정 — **37 → 16**

| | v8(알림 전) | 차단 전 | **차단 후** |
|---|---|---|---|
| 권한 수 | 13 | 37 | **16** |

순수 증가는 셋뿐이다: `POST_NOTIFICATIONS` · `RECEIVE_BOOT_COMPLETED` ·
`BIND_GET_INSTALL_REFERRER_SERVICE`(위 ⏭). **기존 13개 중 사라진 것은 없다** —
`blockedPermissions`를 넓게 쓰다 멀쩡한 권한을 같이 지우는 것이 이 작업의 진짜 위험이라
차집합을 양방향으로 확인했다.

### 권한은 **토글을 켤 때** 묻는다

앱 시작 시 묻지 않는다 — 기둥 1이다. 일기를 쓰러 온 사람에게 첫 화면이 권한 팝업이면 안 된다.

- 토글 ON → 권한 요청 → **거부하면 토글을 되돌리고** 왜 안 되는지 그 자리에 적는다.
  켜진 채로 안 오는 것이 최악이다(지금 *"준비 중이에요"* 가 막고 있던 오해와 같은 종류다).
- 이미 거부한 뒤 다시 켜면 OS가 다시 묻지 않는다 → **설정으로 보내는 안내**가 필요하다.

## 6. ⚠ 예약된 알림은 **예약 시점의 언어로 굳는다**

로컬 알림은 문자열을 OS에 넘겨 저장한다. 그래서 언어를 바꿔도 **이미 예약된 7건은 옛 언어로 온다.**

`CLAUDE.md` §9.1 규칙 2(*"DB에는 코드/id만 저장한다"*)가 막으려던 것과 **같은 병**인데,
여기서는 저장소가 우리 DB가 아니라 OS라 그 규칙을 적용할 수 없다.

→ **언어를 바꾸면 예약을 전부 지우고 다시 잡는다.** 시각 설정을 바꿀 때도 같다.
   재예약은 싸다(7건). 안 하면 언어를 바꾼 사람이 일주일 동안 옛 언어 알림을 받는다.

### ⚠ 시각 표기는 번역이 아니라 **틀**이다

`date.timeOfDay`는 문장이 아니라 **자리표시자 배치**다. `{{hour24}}` · `{{hour12}}` ·
`{{minute}}` · `{{meridiem}}` 넷을 주고 **그 언어가 쓰는 것만 쓰게** 한다 — 날짜(`date.full` 등)와
같은 규약이다(§9.1 규칙 3).

| | 틀 | 21:00 |
|---|---|---|
| ko | `{{meridiem}} {{hour12}}:{{minute}}` | 오후 9:00 |
| en | `{{hour12}}:{{minute}} {{meridiem}}` | 9:00 PM |
| zh-Hans·zh-Hant | `{{meridiem}}{{hour12}}:{{minute}}` | 下午9:00 |
| **ja** 및 나머지 10개 | `{{hour24}}:{{minute}}` | 21:00 |

🔴 **일본어를 12시간제로 뒀다가 자정에 틀렸다.** `formatTimeOfDay()`가 0시를 `hour12 = 12`로
접는데(ko `오전 12:30` · en `12:30 AM` · zh `上午12:30`는 전부 맞다) **일본어만 `午前0:30`이
맞다.** 언어마다 0-vs-12 규칙을 코드에 넣는 대신 **일본어를 24시간제로 바꿨다** —
일본에서 표준 표기이고, 코드에 분기를 하나도 안 늘린다.

⚠ 24시간제 언어도 `date.am`·`date.pm`을 **비워두지 않는다.** 지금은 틀이 안 쓰지만,
나중에 12시간제로 바꿀 때 값이 없으면 그 언어만 조용히 빈칸이 된다.

## 7. 화면

```
설정 › 알림 › 기록 리마인더        토글
                                  ON이면 그 아래 시각 행이 열린다
설정 › 알림 › 알림 시각            21:00   → 시간 선택 시트
```

- 토글이 OFF면 시각 행을 **보여주지 않는다.** 못 쓰는 설정을 회색으로 남겨두지 않는다.
- 문구는 전부 `t()`. 새 키는 `settings.reminder*` · `notification.*`.
  ⚠ `notification.*`(알림 본문)과 `settings.reminder*`(설정 UI)를 **섞지 않는다** —
  전자는 OS로 나가 굳고(§6) 후자는 화면에서 매번 다시 읽힌다. 성질이 다르다.

| 🔴 **오늘 쓰면 오늘 것만 사라진다** | ✅ 8/21 저장 → **8/21만 빠지고 6건 남았다.** 이 기능의 유일한 요구 |
| 시각 변경 → 전체 재예약 | ✅ 22:15로 6건 전부 이동. 오늘은 계속 제외 |
| 토글 OFF → 전체 취소 | ✅ 0건 |
| 알림 채널 | ✅ `mId='reminder'` · `mImportance=3`(DEFAULT) · 이름 `기록 리마인더` |
| 재부팅 후 예약 생존 | ⏳ 실기기 |
| 권한 **거부** 경로 | ⏳ 실기기 — "다시 묻지 않음" 상태를 만들어야 확인된다 |

⚠ 위는 **에뮬레이터(API 35 · `sadojeon`)** 실측이다. 시각 표기(`오후 9:00`)와 시트 초기 스크롤
(21시가 보이는 위치)도 화면으로 확인했다 — 후자는 `contentOffset`이 iOS 전용이라 `scrollTo`로
고친 부분이다.

⚠ 남은 둘은 **에뮬레이터로 답이 안 나온다.** 재부팅 생존은 실제 재부팅이 필요하고,
권한 거부는 "다시 묻지 않음" 상태를 만들어야 확인된다.

### ⚠ 에뮬레이터에 릴리스 빌드가 깔려 있으면 **디버그를 덮어쓸 수 없다**

`INSTALL_FAILED_UPDATE_INCOMPATIBLE: signatures do not match`. 업로드 키로 서명된 v8이
깔려 있는데 디버그 키로 만든 APK를 같은 패키지에 올리려 해서다.

🔴 **지우기 전에 안에 뭐가 있는지 본다.** `adb uninstall`은 앱 데이터를 함께 지운다.
에뮬레이터라 비어 있을 줄 알았는데 **일기 8개가 들어 있었다**(스토어 스크린샷용 시드).
`databases/`는 비어 있고 실제 파일은 `files/SQLite/jogak.db`에 있다 — **거기만 보고
"비었다"고 판단하면 틀린다.**

```
adb root
adb shell ls -la /data/data/com.son0925.jogak/files/SQLite/     # jogak.db · -wal 크기를 본다
adb shell "cp /data/data/com.son0925.jogak/files/SQLite/jogak.db* /data/local/tmp/ && chmod 666 /data/local/tmp/jogak.db*"
MSYS_NO_PATHCONV=1 adb pull /data/local/tmp/jogak.db <백업경로>   # ⚠ Git Bash는 경로를 망친다
```

⚠ **`-wal`을 함께 가져온다.** 본체가 4KB인데 `-wal`이 156KB일 수 있다 — WAL을 두고 오면
백업이 **빈 DB**다. 가져온 뒤 sqlite로 한 번 열면 체크포인트되어 한 파일로 합쳐진다.

#### stg로 나란히 까는 길은 **막다른 길이었다**

패키지를 `.stg`로 바꿔 공존시키려 했으나 자동링크 산출물(`ReactNativeApplicationEntryPoint.java`)이
**옛 네임스페이스의 `BuildConfig`를 계속 가리켰다.** 아래를 전부 해도 안 고쳐졌다:

| 시도 | 결과 |
|---|---|
| `APP_VARIANT=stg npx expo run:android` | prebuild를 다시 안 해서 **prod 그대로** 빌드 |
| 생성 디렉터리만 `rm -rf` | `--build-cache`가 **되살렸다** |
| `--no-build-cache` | 생성 태스크가 `UP-TO-DATE`라 **안 돌았다** |
| `gradlew clean` | 같음 |
| `rm -rf android/app/build` | 이번엔 CMake(arm64)가 깨졌다 → `-PreactNativeArchitectures=x86_64` |

→ **결론: 데이터를 백업하고 prod 패키지에서 그대로 테스트하는 것이 싸다.**
   패키지를 바꾸는 것은 공짜가 아니다.

🔴 **stg로 prebuild했으면 반드시 prod로 되돌린다.** 안 되돌리고 릴리스를 구우면
`.stg` 패키지의 AAB가 나오는데 Play는 그것을 **다른 앱**으로 본다.

```
npx expo prebuild --platform android --no-install    # 서명 env를 함께 준다
grep -n "applicationId\|namespace" android/app/build.gradle   # 눈으로 확인
```

⚠ `android/local.properties`는 prebuild가 만들어주지 않는다. 없으면 `SDK location not found`로
죽는다 — `sdk.dir=C:/Users/<user>/AppData/Local/Android/Sdk` 한 줄이면 된다.
